# 检索历史失败与复用边界

用 [归档规范](08_reporting.md) 定位数据根。按阶段、父配置、触发机制、环境、语义和失败点搜索台账，再由证据列找到材料或案例。重启历史方向前写明已变化的前提、能区分旧死因的观察和最便宜的重开探针。

| 状态 | 留下什么 | 何时重开 |
|---|---|---|
| 未执行 / 历史待跑 | 计划时点、阻塞或取消原因 | 有当前任务授权且未失去价值 |
| 证据缺失 | 缺文件、窗口、身份或未核对侧 | 有可恢复的证据，或补采影响决策 |
| 路径未命中 | 静态与实际加载路径、回执 | 修正加载后先做命中探针 |
| 集成或资源失败 | 接口/阶段、首个报错、完整步数、可用产物 | 已验证接口或显存前提改变 |
| 质量门失败 | 指标、阈值、方向、尚未执行步骤 | 有新机制或实质修正，先重走必要前置门 |
| 有效阴性/中性 | 机制已生效、可比窗、阈值与实际差 | 比较边界改变或有新证据 |

运行失败后的产物可按实际写入节点或任务所有者单独核验。用本轮完成标记、指纹、负载结构和允许的副作用范围判断能否复用，保留入口真实退出值和产物裁决。未命中运行如配置、工作负载和其余观察足够匹配，可作为条件对照，保留原假设未验证这一状态。技术方向的失败边界以本次栈、接口和验证范围为准。
