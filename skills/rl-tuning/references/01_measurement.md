# 指标、对照与灰区

立项记录 token 分子（packed、response、有效或其他）、墙钟计时边界、设备数与统计窗口，声明预热剔除和输出长度分布。逐步吞吐为 tokens / wall / devices。逐步吞吐算术平均与聚合吞吐 Σtokens / (Σwall × devices) 一般不同。开跑前钉住一种主口径，另一种可以作为审计结果。

固定工作量时，目标吞吐 T 对应每步时间上限 tokens / (devices × T)。以各计分步分别核算缺口。变化来自响应缩短、跳样本或掩码变化时，报告训练信号工作量及质量变化，避免将工作量减少直接计为工程提速。

| 对比层级 | 用法 |
|---|---|
| 同工作负载、同机、同窗口，固定批与随机状态或重复成对 | 估计变更的效果，记录散布和配对条件 |
| 同机相邻运行，在线采样或顺序不同 | 报实测差，结合阶段及 workload 判断可归因部分 |
| 跨机、跨版本或跨度不同 | 提供外部参照或提出假设。量化可比性需要额外的控制臂和校准 |

首步和单步通常用于筛选。报告预热、全程退出、重复次数、各计分步和散布。把项目最小收益与基线噪声同时纳入判据。例：项目可预登记 2% 收益要求，但基线重复波动为 5% 时，需要更强的配对或扩大窗口。比目标快多少、变更臂比对照快多少、能归因多少，分别写清。

阶段计时需标角色、rank、时钟和单位。在有并行的窗口上取跨 rank 最慢路径或时间区间并集，列明包含关系和未解释的墙钟。采样计数、累计通信、host 阻塞和峰值单算子加速用于提出假设，端到端采用经过对照的暴露时间和实际 wall。保留整步收益为负但机制成立的结论。

派生指标与实测冲突时，先从同一 run 的原始 token、设备数和 wall 复算，并审计参与推导的基线。两份直接读数仍不一致时，保留出处和比较窗口，标记争议维度，待定位差异后更新裁决。
