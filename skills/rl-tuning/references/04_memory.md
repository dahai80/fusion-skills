# 全步显存与 OOM

记录每张卡的容量、峰值占用、采样间隔和最小观测余量，用进程和阶段锚定。整卡 HBM 是系统资源门。allocated、reserved、allocator free 和请求大小是定位进程内失败的证据。数据单位一致后再比较。离散采样可能漏掉尖峰，标清覆盖、时间戳和最紧卡。

按实际共驻做账。分开列权重、梯度、优化器、峰值激活、logits/CE、分片聚合、KV/图工作区和其它进程的占用。把 rollout sleep、Reward/Ref 上下卡、Actor 回驻、refit 和下一步 KV wake 的重叠画在同时间轴上。reserved 下降可以作为机制证据，是否释放整卡余量要复核。跨节点关联先对齐时钟，只有时间吻合时只定位到窗口，具体分配者还要对照 allocator 或其他直接证据。

OOM 后记首个失败 rank、阶段、分配点、请求量、allocator 指标和终态。比较同阶段实测，避免把失败窗和全程峰混用。先尝试最小的资源变量，确认样本覆盖和梯度契约。缓解某阶段 OOM 后，重新扫全窗口最紧卡。工作负荷峰值由项目给出，留量阈值由项目和验收窗口决定。
