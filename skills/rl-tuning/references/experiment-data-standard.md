# RL 调优实验与数据记录标准 · v1.0

适用于 GRPO/PPO 调优的新记录和历史回填。本版规定新记录的最少字段，历史摘录按实际证据回填。首次使用时，把[空白登记表](../templates/id-register.tsv)复制到项目数据根的 `data/experiments/id-register.tsv`。所有分工共用该表。

## 1. 实验 ID 与运行 ID

| 对象 | 正式格式 | 定义与发号时点 |
|---|---|---|
| 实验 ID · `experiment_id` | `RL-EXP-DEMO-0001` | 对应一个待裁决的假设或预登记的对照问题。立项时登记项目代码、父配置、对照、变量、判据和预算。 |
| 运行 ID · `run_id` | `RL-RUN-DEMO-0001-01` | 对应一次有独立身份的提交、执行或暂存尝试。准备提交前登记，记录所属实验、用途及状态。 |
| 现场标识 · `source_run_id` | 如 `trainer_run_001` | 保留调度器、日志或目录中的原名。历史实验名和车次分别映射到相应对象，映射须有来源和核验状态。 |

- 项目代码、实验序号和实验内运行序号由 RL 工作区登记表维护。编号唯一、固定、作废后保留。支持 Claude 与归档方并行时，提前登记或预留号段，共用同一编号登记表。阶段、日期和结论写字段。
- 同一候选和裁决问题的复跑、故障重提、短窗或长窗验证，保留实验 ID，新增运行 ID，分别记录实际条件、运行用途和协议版本。一次连续恢复用新运行记录连接 `resume_from_run_id`，并标明恢复的 checkpoint 与步号，避免将续跑当作独立重复。机制 probe 和端到端验收若针对不同裁决问题，各有自己的实验记录。
- 换对照来回答新问题、修改候选处理或训练语义，或者引入预登记实验外的新变量，开新实验并关联父实验。预登记的固定批 A/B 或参数扫描共用一个实验。每次独立启动各用一个运行 ID。一次启动覆盖多个臂时，逐条观测补 `arm_id`，记录臂顺序、重复和预热。
- `parent_experiment_id` 记录配置演进，`baseline_run_id` 绑定用于计价的实际对照运行。冻结或基线报告也要绑定实际生效配置的版本或指纹。里程碑先后、配置继承和可定量比较各有自己的证据。

## 2. 人读报告与结构化记录

沿用 RL 工作根下现有的轮次目录。每轮用总览、计划、分析、报告和复盘交接，报告引用表中的实验、运行、计分和证据。表是结构化检索入口。测量由原始日志或可定位的历史摘录支撑。

| 记录 | 粒度 | 最少记录 |
|---|---|---|
| 实验台账 `ledger.tsv` | 一实验一行 | 实验 ID、目标、假设、父实验、对照运行或待选状态、拟改变量、保持条件、语义差异、预登记判据与版本、当前裁决和证据。 |
| 运行清单 `runs.tsv` | 一尝试一行 | 运行 ID、实验 ID、现场标识、用途、起止时间和时区、设备/节点、配置与入口版本或指纹、拟跑和完成步数、运行状态、观察到的退出码、产物与来源。生效配置包含模型/checkpoint、数据版本、框架/镜像版本、并行策略、rollout/RM/Actor/Ref 设置和 profiler 状态，正文可引用有版本的快照。 |
| 逐步数据 `steps.tsv` | 一运行、臂、步一行 | 运行 ID、步号、实际计数、计数定义、step wall 秒数、卡数、预热/计分标记和原始出处。按需补各 RL 阶段时间、样本和响应长度、背压或长尾数据。显存与质量原始样本可独立存放，引用时带运行 ID、节点/rank、采集来源、窗口和单位。 |
| 计分 `scores.tsv` | 一运行、臂、指标、口径、窗口、来源一行 | 计分 ID、运行 ID、指标名与口径版本、窗口、公式或聚合方式、值、单位、原始精度、原报或复算来源、计分有效性和证据。原报与复算并存时分别登记。跨运行差值由分析引用双方得分。 |
| 裁决及历史映射 | 一裁决或别名映射一条 | 裁决绑定候选及实际对照运行、所引用的计分、证据与判据版本。历史映射记录旧实验名、车次或暂用别名、来源范围、对应标准 ID 和核验状态。 |

新记录把空值写成空字段并登记原因，例如 `unknown`、`not_collected`、`not_applicable`。运行状态单列。待跑或仅暂存、提交被拒、成功、失败、中止和终态待查可独立检索。实际产物及完整性单独记录。历史身份待查的条目进入取证清单，保留原文和定位线索，核实后再连到运行明细。已定位运行但只有汇总值的历史记录可先入账，标记来源类型和可复算范围。

## 3. 指标与判收

- 立项时写清 token 分子（如有效 prompt+response token 或 response token）、计时起止、节点和卡数、计分步、预热、保存与评估开销。一步吞吐为 `tokens / (wall_s × devices)`。固定卡数时，窗口聚合为 `Σtokens / (Σwall_s × devices)`。逐步算术均值照原协议独立记录。训练步吞吐、扣开销吞吐、整作业吞吐各采用明确的时间边界。
- 按原精度保留分子、分母、设备和取数位置。四舍五入仅用于展示。若历史资料只有近似分子或墙钟，派生值带“近似复算”标记并保留原报值。原报与复算有冲突时记录差异、单位及待核处，经追溯再更新裁决。
- 用同机同负载、配置差异可核、同窗口和计时边界的对照估计收益。对 GRPO 还要核对 checkpoint、数据/批次、采样与响应分布、RM、old/ref log-prob、loss 和实际更新量。跨栈、跨机和不可对齐的历史窗口可做参照。多项共变时记录组合效果，单项归因依赖隔离对照。
- 裁决逐项记录运行完整性、性能、机会成本、路径命中、数值/训练质量、训练语义、最紧卡显存余量和稳定性/发布验收。预登记的完整性条件失败时，已完成步可留作诊断，窗口主分标为无效。负结果、OOM、配置门失败和环境失败保留，复盘可按各自证据支持的范围使用。
- 判据变更登记来源、时间、范围、新旧版本和各自裁决。按现有测量复判，留存各次裁决。无 profiler 计分与采集用途各自绑定运行 ID。历史规则经 RSI 回放、反例和新轮次验证后进入正式流程。

## 4. 证据与验收

- 每条关键观测或裁决链接到本地文件及行号、日志步号/时间戳，或远端机器和路径。用现有材料索引记录源文件定位及可取得时的大小、指纹、验证时间。大型 profile 和只在远端节点的文件以索引为入口，后续按取证需求读取。
- 分别记录来源类型（原始日志、历史摘录、复算、待核线索）和核验状态。仅知道远端有文件时记为已定位。正文或表格用到数值时可沿引用追到实际读过的材料。
- 归档抽查覆盖编号唯一、引用可连接、父配置和对照可定位、成功与失败均有终态或缺口、有效吞吐可复算、历史原名可反查。人可从里程碑报告回查证据，Agent 可用 ID 检索相同记录。

## 5. 正式登记和复查

本页示例的项目代码为 `DEMO`。不同项目先取无冲突的项目代码。实验号从项目内 0001 起递增，运行号沿所属实验从 01 起递增。位数不足时补零，超出展示宽度时继续递增。编号中的顺序表示登记顺序。日期、运行状态与晋级结果由记录内容给出。

1. 在共用登记表按项目、来源与旧名查重。先确定谁负责本批写入，串行追加；多人并行时，由同一登记人先把各自需要的编号写成预留行，再分头维护内容。各镜像读取同一份已登记结果。
2. 按已占用的最大序号加一，包含已预留及作废的号。写入 `id、kind、experiment_id、legacy_alias、source_label、record_path、issued_on、id_status`。实验行用自身 ID 作 experiment_id，运行行指向所属实验。预留、已发、作废分别记 reserved、issued、void。重复提交沿原登记补写，作废保留原行。
3. 在 record_path 所指的台账或运行表补齐同一主键、历史原名与证据。一个排队中的实验可先有实验号。已分配运行号的暂存尝试可记 staged。发号中断时从已有登记行恢复，完成关联后再交接。跨轮次查运行时先按登记表的 record_path 定位。
4. 报告引用实际对照与候选的 run_id、计分协议和得分。新记录的 baseline_run_id 待定时写明原因，历史组合父链可暂存 source_parent。历史 run_ids 只列已正式登记的运行，旧台账里的尝试名或臂名保存在 legacy_run_refs。历史覆盖表以来源、旧名、来源标签定位，能绑定的记录另填正式 ID。
