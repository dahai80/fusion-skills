# 质量与语义验收

立项固定模型与概率来源、采样、奖励、mask、loss、clip/KL、归一化、更新步数和权重版本。把影响训练目标、样本分布、数值精度或训练数据完整性的差异单独登记。历史 E/S 编号可承载项目分类，但授权、数值差异和实际运行状态仍须分栏。

1. 路径审计。核对完整配置与实际计算图，必要时记录关键张量身份及 rank。
2. 固定输入验证。以相同 checkpoint、批次、mask、seed 和形状运行对照。核对逐 token LP、KL、ratio、clip 状态、损失分项、梯度有限性、norm、误差分布和异常样本。近零分母用绝对误差和范数下限。验证更新时可核对 optimizer delta。
3. 分布式验证。用真实批次覆盖 rank 差异、长序列和边界形状。A/B 与 B/A 用于检查顺序、热身及分配器干扰。根据问题决定是否需要成对固定批和独立重复。
4. 端到端 canary 和正式验收。看 prompt/response 长度、奖励和有效样本、KL/clip、loss/grad、吞吐、HBM 和失败信号。预登记正式窗口、重复和接受域。短跑健康与长期发布判定单列。

性能和质量阈值应从父配置噪声、变更风险和验收目标确定。例如固定批 loss 1%、grad 10% 可做某项目初筛的候选阈值，仍须说明指标定义和适用条件。更换采样、冻结或降频 Ref、跳过 old 重算以及修改 KL 的变更，必须写明概率数据流、效果和项目授权。
