# 华为风格一页纸报告

以 [一页纸底稿](assets/onepage-template.html) 为底稿复制改写，不从空白页起稿。底稿里是虚构的示例数据（7B 模型 GRPO 训练两轮调优对比），只用来演示版式，写报告时全部换成本次的实测数据。

## 默认交付

“总结报告 / 汇报”= 一页、不分页，不是多页 PDF，不是 PPTX。用户当次明确要别的形式时以当次为准。

页面长度：宽固定 A4（210mm）；内容放得下就是标准 A4，放不下时页面向下加长，**最长 2 倍 A4（594mm）**，仍是单页 PDF。不为凑长度加内容，重复信息照样先删。

## 版式（照底稿，不自创骨架）

自上而下：
1. 标题（结论式）+ 右上状态标签
2. 范围 / 对比对象 / 统计口径（meta 两列）
3. 红底白字论点条：一句话讲清改了什么、关键数字从多少到多少
4. 四个指标卡（大红数字 + 前后对比）
5. 表 1 关键数据对比：**本轮/改造后列红字浅红底**（`td.cur`）
6. 表 2 措施与效果：编号红字、效果列加粗红数
7. 细项分析：内联 SVG 图，旧=灰线、新=红线，图注“图 N　…”
8. 结论 / 下一步框（红色左边框）
9. 页脚：报告名 · 日期 ｜ 数据来源

配色只用底稿 `:root` 里的红灰：`--red #c7000b`、`--redbg #fbe9ea`、`--panel #f2f2f2`、`--ink`、`--muted`、`--soft`。直角细线，无阴影、圆角彩卡、动画。

## 内容规则

- 对比对象是**上一次正式数据**，写清口径；单次运行不算结论。
- **内部目标值不进报告**，“未达项”也不写。
- 措施命名突出**泛化性**（如“重复输入去重”“均衡分卡”），原理写通用机制，不写本数据集的特定数字。
- **同一指标只出现一次**：顶部卡片有了，细项图就不再画。
- 训练类写清**加权吞吐口径**（全程 token ÷ 卡数 ÷ 全程耗时）；其他主题选对应指标，不机械套 MFU。
- 没有实测数据的指标不用推算值硬画，先问用户。
- 不写“说明/补充”类填充句；必要信息放图注或表内。
- 时间写明时区。

## 小范围创新

- **骨架保持稳定**：版式顺序、红灰配色、字号层级、直角细线和内容规则不动，不整体换风格。
- 每次可挑 1～2 处做小范围创新（新的图形表达、指标卡或表格变体、论点条/图注的新写法），交付时在回复里点明“这次试了什么”，用户满意再固定下来。

## 渲染与验收

```bash
bash scripts/render-onepage.sh 输入.html 新输出目录   # Chrome 无头：先量内容高度，再按 297～594mm 打印单页 PDF，出 2 倍清晰度 p1.png
```

需要 macOS（量页高、出 PNG 用系统自带的 osascript + PDFKit）和 Google Chrome；Chrome 不在默认位置时用环境变量 `CHROME` 指定。输出目录必须不存在。HTML 主容器须为 `.page`（底稿已是）。脚本会报出页高和“A4 的几倍”；内容超过 2 倍 A4 时直接报错。验收：PDF 确实 1 页；看 p1.png，关键数字清楚、无裁切、无孤字换行、页脚不被挤压。超长时先删重复信息、压缩图高，不缩字号到 7pt 以下。

交付 PDF 和 PNG，文件名用中文标题加日期；源 HTML 和渲染目录留在任务目录。

## 技术讲解 PDF（仅用户要“讲解/解释”时）

多页讲解用 [讲解模板](assets/explainer-template.html)（示例内容为虚构数字）：标题 + 数据截止时间 → 摘要框 → 一、二、三分节（先机制，再图，再数据表）→ 一句话总结框。图为 680 宽 viewBox 内联 SVG，颜色按含义（紫=处理，青=正常/结果好，橙=问题路径，琥珀=标记，灰=中性），图注“图 N　…”。渲染 `bash scripts/render.sh in.html out.pdf [预览目录]`（逐页出 PNG 需 macOS 的 Swift/PDFKit）；逐页看 PNG 后再交付。
